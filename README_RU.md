# dnsbench

[English](README.md) | [Русский](README_RU.md)

`dnsbench` — кроссплатформенная консольная утилита для сравнения задержки и
надёжности DNS-резолверов. Она работает в Linux и нативной 64-битной Windows,
поддерживает IPv4 и IPv6, загружает актуальные списки по странам, принимает
локальные списки и при необходимости сохраняет результат в CSV.

## Возможности

- Нативная реализация на C без сторонних C-библиотек.
- Один исходный файл для Linux и Windows.
- Прямые DNS-запросы по UDP без накладных расходов `nslookup` и PowerShell.
- IPv4- и IPv6-резолверы; запросы `A` и `AAAA`.
- Одиночный, прогретый кешированный и уникальный сценарии.
- Параллельная проверка партиями максимум по 256 серверов.
- Средние значения, число ответов, рейтинг и опциональный CSV.

## Источник данных

Названия и коды стран берутся со страницы Wirewiki
[DNS server index by country](https://www.wirewiki.com/dns-servers/by-country).
Адреса DNS-серверов загружаются при запуске из списков вида:

```text
https://www.wirewiki.com/dns-servers/{код-страны}.txt
```

Например, Казахстан загружается из
[`kz.txt`](https://www.wirewiki.com/dns-servers/kz.txt).

Списки не включены в репозиторий. Проект независим от Wirewiki и не является
официальным или одобренным инструментом Wirewiki. Доступность, классификация,
точность данных и разрешение на использование конкретного резолвера
контролируются третьими сторонами и не гарантируются проектом. Используйте
умеренные параметры и соблюдайте правила соответствующих сетей.

## Методика

Каждый запуск содержит три измеряемых сценария:

1. **Single** — один запрос выбранного имени.
2. **Cached** — один неучитываемый прогрев, затем `-n` запросов того же имени.
3. **Uncached** — `-n` запросов уникальных имён внутри выбранного домена.

Прогрев не входит в статистику. При `-n 5` каждый резолвер получает 11
измеряемых запросов и один дополнительный запрос прогрева.

`Uncached` означает отсутствие точного конечного ответа для сгенерированного
имени. Полностью холодная рекурсия не гарантируется: делегация, отрицательные
ответы и связанные записи могут оставаться в кеше.

По умолчанию запрашивается `example.com` — зарезервированный IANA примерный
домен. Его можно изменить через `-q`.

Серверы проверяются параллельно партиями максимум по 256 адресов. Это защищает
Linux от лимита открытых файлов и ограничивает число сокетов в Windows.
Приблизительная максимальная длительность в секундах:

```text
ceil(число_серверов / 256) * (2 * n + 2) * timeout_ms / 1000
```

Тест может закончиться раньше, если все серверы партии ответят или вернут
ошибку до таймаута.

## Требования

- GCC, Clang или MinGW-w64.
- GNU Make.
- `curl` в `PATH` для режимов Wirewiki. Локальный список не требует `curl`.

MinGW-w64 нужен только для сборки `dnsbench.exe`. Пользователю готового файла
не нужны компилятор, WSL или Cygwin.

## Готовый Windows-файл

В репозитории находится готовый 64-битный [`dnsbench.exe`](dnsbench.exe) для
тех, кто не хочет устанавливать компилятор. Скачайте также
[`SHA256SUMS`](SHA256SUMS) и проверьте файл в PowerShell:

```powershell
Get-FileHash .\dnsbench.exe -Algorithm SHA256
```

Полученный хеш должен совпасть со строкой `dnsbench.exe` в `SHA256SUMS`.
Makefile задаёт фиксированный `SOURCE_DATE_EPOCH`, поэтому неизменный исходник
даёт воспроизводимый Windows-файл и стабильную контрольную сумму.

## Сборка

Linux:

```sh
make
```

Windows со средой MinGW-w64 и GNU Make:

```powershell
make
# либо, в зависимости от установки:
mingw32-make
```

Makefile распознаёт `OS=Windows_NT`, подключает Winsock и создаёт
`dnsbench.exe`.

Кросс-сборка Windows x64 в Ubuntu или Debian:

```sh
sudo apt-get update
sudo apt-get install gcc-mingw-w64-x86-64
make windows
```

Очистка собранных файлов: `make clean`.

## Быстрый запуск

Linux:

```sh
./dnsbench -L
./dnsbench kz
./dnsbench -n 5 -t 150 kz
./dnsbench -n 5 -t 150 -o fr.csv fr
```

Windows PowerShell:

```powershell
.\dnsbench.exe -L
.\dnsbench.exe kz
.\dnsbench.exe -n 5 -t 150 kz
.\dnsbench.exe -n 5 -t 150 -o fr.csv fr
```

Параметры можно указывать до или после кода страны.

## Параметры

```text
Usage: dnsbench [options] SERVERS_FILE
       dnsbench [options] -c COUNTRY_CODE
       dnsbench [options] COUNTRY_CODE
       dnsbench -L

  -q NAME       запрашиваемое имя (по умолчанию example.com)
  -n COUNT      число запросов в каждой серии (по умолчанию 5)
  -t MS         таймаут запроса в миллисекундах (по умолчанию 1000)
  -T TYPE       тип запроса: A или AAAA (по умолчанию A)
  -p PORT       порт DNS-сервера (по умолчанию 53)
  -o FILE       сохранить отсортированный результат в CSV
  -c CODE       загрузить и проверить список страны Wirewiki
  -L            показать найденные на Wirewiki страны
  -h            показать справку
```

`dnsbench kz` эквивалентно `dnsbench -c kz`. Не путайте `-n` и `-t`:
`-n 150` отправляет по 150 запросов в каждой серии, а `-t 150` задаёт таймаут
150 мс.

## Чтение результата

```text
Rank | DNS server      |    Single |    Cached |  Uncached |   Average |    OK/All
1    | 103.116.198.226 |     30.47 |     31.25 |     32.05 |     31.25 |   11/11
```

- **Single**, **Cached**, **Uncached** — среднее время сценария в мс.
- **Average** — среднее всех успешных измеряемых запросов.
- **OK/All** — корректные ответы и общее число измеряемых запросов.
- Прочерк означает отсутствие корректного ответа в сценарии.

Отвечающие серверы сортируются по общему среднему. Низкая задержка при плохом
`OK/All` не означает хороший DNS — учитывайте надёжность вместе со скоростью.

## CSV

CSV создаётся только при явном `-o FILE`:

```sh
./dnsbench -n 10 -t 500 -o kz.csv kz
```

Столбцы:

```text
rank,dns_server,single_ms,cached_ms,uncached_ms,average_ms,successful,total
```

Отсутствующие значения остаются пустыми. Существующий файл перезаписывается.

## Локальный список

Вместо кода страны можно передать текстовый файл. Каждая строка содержит
буквальный IPv4- или IPv6-адрес и необязательное имя. Пустые строки и текст
после `#` игнорируются.

```text
# Public resolvers
1.1.1.1                 Cloudflare
8.8.8.8                 Google
2606:4700:4700::1111    Cloudflare IPv6
```

```sh
./dnsbench servers.example.txt
./dnsbench -n 10 -t 500 -o results.csv servers.example.txt
```

В терминале и CSV сейчас выводится только IP-адрес.

## Коды завершения

- `0` — ответил хотя бы один резолвер.
- `1` — ошибка аргументов, загрузки, файла или локальной системы.
- `2` — не ответил ни один резолвер.

## Платформенная реализация

DNS-пакеты, сценарии, статистика, сортировка и CSV общие. Linux использует
POSIX-сокеты, `poll` и `clock_gettime`; Windows — Winsock 2, `WSAPoll` и
`QueryPerformanceCounter`.

Эквивалентные запросы не гарантируют одинаковое время на разных ОС: влияют
маршруты, VPN, межсетевые экраны, защитное ПО, нагрузка и состояние кеша.


Готовый Windows-файл намеренно хранится в репозитории для прямого скачивания.
Собранный Linux-файл, CSV и скриншоты исключены через `.gitignore`. Бинарники
также можно прикладывать к тегированным GitHub Releases. GitHub Actions собирает
Linux- и Windows x64-артефакты.
